# Design

## Context

用户 7 条反馈里有 3 条是故障、4 条是体验。故障优先。

## Goals / Non-Goals

**Goals:**

- 补点从「>120 秒且失败」回到可用状态。
- 入口不再因为上游失败而消失。
- 指南看起来像分析，而不是源码。

**Non-Goals:**

- 本轮不做页面内出图（第 1 条的一半）与地图圈注风险点（第 2 条），
  它们需要在本页引入地图，改动面大，单独一轮做。
- 不做 OSM 岔路（第 8 条），用户已同意先修别的。

## Decisions

### D1 · 主查询只取节点

实测：`out geom tags` 会把水域面的全部顶点拉回来，查询从 42 秒涨到 120 秒以上。
而垭口、山峰、营地、村镇**几乎全是节点**，节点本身带坐标，`out tags` 足够。

河流必须几何才能判过河，所以单独发一次；它失败只是少一类「过河」标注，
不该拖垮整次补点。

### D2 · 重试时轮换代理

实测 mihomo 的 7891 曾经直接拒连，而 7890/7893 正常。
固定一个代理端口等于把可用性绑在单点上。改为每次重试换一个端口。

### D3 · 对话入口常驻但禁用

入口消失比「点击后告诉你还没数据」更糟：用户会以为功能没做。
改为常驻 + 禁用态 + 明确提示。

### D4 · 提示词用「禁止清单」压套话

只写「要具体」对模型没用。改为显式列出禁止出现的表述
（导入手机 / 保持离线 / 徒步鞋头灯登山杖），并给出**允许提装备的条件**，
把「什么都提」变成「满足条件才提」。

### D5 · 风险带里程

「4 处发卡弯」没有位置信息等于没说。转向本来就有 km，直接带上。

## Risks / Trade-offs

- **[节点查询可能漏掉面状地物]** → 湖泊里既有节点也有面，本轮只取节点版本；
  面状湖泊作为已知缺口记录，后续可单独补。
- **[河流查询被跳过]** → 结果里少了「过河」类标注，其余不受影响。
- **[迷你 Markdown 渲染不通用]** → 只覆盖本页产出的语法，够用且无依赖。
