# Proposal

## Why

徒步结束后需要一张能直接发朋友圈、贴进游记的「分析长图」：同一张图里既有带底图的
轨迹，又有总览数据、配速曲线、海拔剖面和 1km 分段表。

现在回放页只能导出「地图 + 图例」的矩形截图，统计与分段数据还得另外手工记，
做一次分享要拼好几次图。项目里已经有成熟的纯前端 canvas 出图能力
（`player.html` 的 `exportPng`：自算投影、自贴瓦片、绕开 html2canvas），
复用这套思路补一个专注「导入 GPX → 长图」的页面，成本最低、也不给服务器加负担。

## What Changes

- 新增独立页面 `web/report.html`（经 `/gpx/report.html` 访问）：拖入或选择 GPX，
  一键生成宽 1080px 的竖版分析长图 PNG。
- 长图自上而下由五块组成：
  1. **轨迹图**：Windy 户外底图，轨迹**按速度**渐变着色（不是按海拔），标注起终点与速度图例；
  2. **总览数据**：里程、耗时、均速、累计爬升、最高海拔；
  3. **配速曲线**：纵轴配速（越快越高），剔除 GPS 尖峰；
  4. **海拔剖面**：按里程画海拔，标出最高/最低点；
  5. **1km 分段表**：按累计里程每 1000m 切一段，末段不足 1km 单独成行并标实际距离；
     每行给用时、配速、均速、爬升，最快/最慢段用底色高亮。
- **数据降级矩阵**：GPX 没有时间戳则不出配速曲线、分段用时填「—」；没有海拔则隐藏
  爬升与最高海拔；没有心率/步频则整列隐藏（本仓库的 Garmin 样例 GPX 只有坐标/海拔/时间）。
- 门户新增「分析长图」入口卡片。
- 纯前端：除 `/api/tile/windy` 取瓦片与 `/api/tilecache/stats` 显示缓存用量外，
  不调用任何服务端接口；不引入新的第三方库（页面不需要 Leaflet）。

## Capabilities

### New Capabilities

- `analysis-report`: 独立分析长图页 —— GPX 导入、按速度着色的 Windy 轨迹图、
  总览数据、配速与海拔曲线、1km 分段表、长图预览与导出。

### Modified Capabilities

- `service-portal`: 「统一入口」需要新增分析长图页的入口卡片。

## Impact

- 新增：`web/report.html`（页面 + 内联 JS，无构建步骤，不新增依赖）。
- 修改：`web/portal.html`（入口卡片）、`tests/test_player.py`（静态断言与 node 语法检查）、
  `tests/test_e2e.py`（页面可被静态服务返回）。
- 不改：后端接口、瓦片代理与限流策略、部署配置。静态页由既有 StaticFiles 以 `/` 与
  `/gpx` 双前缀提供，Caddy 无需改动。
- 合规：瓦片仍经服务端代理与缓存，页面只在用户点「生成」时取当前区域的固定缩放级别瓦片，
  且限制单次瓦片数量；不提供批量/对外服务。
