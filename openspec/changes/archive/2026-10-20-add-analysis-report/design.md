# Design

## Context

- 前端是无构建步骤的原生 JS，页面放在 `web/`，由 `app/main.py` 的 StaticFiles
  以 `/` 与 `/gpx` 双前缀直接提供；Caddy 只做前缀剥离，不需要为新增页面改配置。
- `web/player.html` 已有一套经过实战的 canvas 出图方案（`exportPng`）：
  自算 Web Mercator 投影（`projectPoint`）、按当前视野拼 256px 瓦片、
  用独立 `Image` 重新拉瓦片避免污染画布、绝不使用 html2canvas。
  历史上 html2canvas 对跨 pane 的 SVG `<path>` 支持极差，导出图里轨迹整条丢失。
- Windy 瓦片浏览器不能直连（响应头违反 CORS 规范，Chrome 判
  `ERR_BLOCKED_BY_ORB`），必须经 `/api/tile/windy`；服务端有磁盘缓存与
  「服务器 → 上游」限流，前端不做排队限速。
- 测试约定：`tests/test_player.py` 做 HTML 静态断言、用 `node --check`
  检查内联 JS、并用正则抽出纯函数在 node 里跑断言。
- 样例 GPX（Garmin Explore 导出）只有 `lat/lon/ele/time`，没有心率与步频，
  所以降级路径是常态而非边缘情况。

## Goals / Non-Goals

**Goals:**

- 一张图里同时给出轨迹图、总览、配速曲线、海拔剖面与 1km 分段表，
  版式接近手机端分享卡片的竖版长图。
- 出图结果与当前浏览器窗口大小无关（版面完全由内容决定）。
- 在缺少时间、缺少海拔、缺少心率/步频的 GPX 上都能出图，只是少对应的块或列。

**Non-Goals:**

- 不做多轨迹叠加与手工标注（那是回放页的职责）。
- 不做服务端渲染，也不新增 Pillow 等依赖。
- 不做回放页 → 分析页的轨迹交接；本变更里分析页自己导入文件。
- 不做 PNG 以外的输出格式（PDF / SVG / 分享链接）。

## Decisions

### 1. 独立页面 `web/report.html`，单文件内联 JS

- 分析长图是「一次性交付物」，与回放页的交互式地图是两种东西；独立页面不用背着
  图层列表、标记、图例拖拽等状态，逻辑更短也更好测。
- 代价是 GPX 解析要自带一份。这里只保留 `trkpt` 解析（`lat/lon/ele/time`），
  约 60 行，不复制 KML/KMZ/配色/导出方案等回放页专属代码。
- 备选：给回放页加按钮。用户已明确选择独立页面，且回放页已 1758 行，
  再塞长图渲染会显著抬高回归风险。

### 2. 不用 Leaflet，纯 canvas 画轨迹图

- 长图是静态的：不需要缩放、拖动、瓦片预取。用 Leaflet 反而要处理 CSS 高度、
  容器尺寸、瓦片 pane 层级等与出图无关的问题。
- 直接复用回放页验证过的公式：给定 `zoom` 与视野左上角像素原点，
  由经纬度算像素；瓦片按 `floor(origin/256)` 铺格。
- 取瓦片用 `crossOrigin='anonymous'` 的独立 `Image` 重新请求同源的
  `/api/tile/windy/...`。同源请求不会污染画布，`toBlob` 才能成功。
- 备选：Leaflet + html2canvas —— 已知会丢轨迹，且会把缩放控件画进图里，否决。

### 3. 版面几何（固定值，便于测试断言）

| 区块 | 尺寸 / 规则 |
|---|---|
| 整图宽度 | 1080 px（导出 1×；可选 2×） |
| 左右边距 | 48 px |
| 轨迹图区块 | 1080 × 1440（固定 3:4，含图头与来源标注） |
| 总览区 | 大号里程 + 2×3 指标栅格 |
| 配速曲线 | 高 300（含坐标轴与刻度） |
| 海拔剖面 | 高 240 |
| 分段表 | 表头 64 + 每行 64 |
| 图底 | 数据来源 + 生成时间 |

整图高度 = 各区块高度之和（可隐藏区块按 0 计），先算高再建画布。

### 4. 轨迹按速度着色（用户明确要求）

- 逐步速度 = 相邻点距离 / 时间差；时间差为 0 或时间回退的点跳过。
- 平滑：对速度做滑动均值（窗口约 15 个点，且不小于 100m 的滑动距离），
  目的只是让颜色过渡自然，不改变统计值。
- 色带取值域：取平滑后速度的 P10–P90 分位，避免一两个 GPS 尖峰把整条线压成单色。
- 色带五档：慢 `#3d7bd9` → `#46b97a` → `#d8cf4a` → `#f0a33c` → 快 `#e2513c`；
  速度低于 0.5 km/h 视作停顿，用中性灰 `#9aa7b4`。
- 图例放在轨迹图左下角，标「慢 3.1 km/h ── 5.4 km/h 快」。
- 备选：按海拔着色（参考截图的做法）。用户要求速度为着色依据，因为速度更能看出
  体能分段与休息点；海拔改由剖面图承担。

### 5. 1km 分段算法

- 用累计里程数组，从 0 开始每 1000m 找落点：在跨过边界的相邻两点之间按距离
  线性插值取边界点（含插值后的时间与海拔）。
- 末段不足 1000m 时照常成行，距离列显示实际值（如 `0.42`）。
- 每段指标：用时 = 边界时间差；配速 = 用时 / 距离；均速 = 距离 / 用时（换算 km/h）；
  爬升 = 段内所有正海拔差之和。
- 最快/最慢段按配速排序取首尾，分别用浅红/浅绿底色；不足 3 段时不做高亮。
- 缺时间戳时仍然分段，只是用时/配速/均速列显示「—」。

### 6. 配速曲线：滚动均值 + 纵轴反向

- 单点的「瞬时配速」噪声太大，改用固定距离窗口（约 200m）内的速度换算配速。
- 纵轴反向（数值越小越靠上），与参考图一致；刻度用 `m'ss"` 格式。
- 速度接近 0 的点不连线，断开成多段，避免为休息时间画出一根冲顶的尖柱。
- 海拔剖面用原始累计里程与海拔，画面积填充 + 最高/最低点标注。

### 7. 降级矩阵（版面自适应）

| 缺失项 | 表现 |
|---|---|
| 无时间戳 | 不出配速曲线；耗时/均速/分段用时显示「—」；顶部提示 |
| 无海拔 | 不出海拔剖面；隐藏累计爬升与最高海拔 |
| 无心率/步频 | 分段表整列不出现 |
| 瓦片失败 | 底图留浅色底纹，轨迹与其它区块照常 |

区块被隐藏时其高度按 0 计，后续区块整体上移，避免空白。

### 8. 出图流程与防卡死

1. 解析 → 派生序列（累计里程、速度、配速、平滑值）；
2. 计算版面高度、建立 canvas；
3. 并发取瓦片（并发 6，单张失败重试 1 次，总数上限约 60 张；
   用缩放级别 clamp 保证不超上限）；
4. 依次绘制轨迹、统计、曲线、表格、图例；
5. `toBlob` 下载，同时把缩略图放进页面预览。
- 生成期间按钮禁用并显示进度（解析 / 取瓦片 x/y / 绘制）。
- 若 `canvas.width * canvas.height` 超过安全阈值（约 1.6 亿像素），
  自动把倍率降到 1× 并提示。

### 9. 测试策略

- `tests/test_player.py` 增加：页面存在、关键要素字符串、内联 JS 通过
  `node --check`、页面内引用的元素 ID 都存在、页内链接都带 `/gpx` 前缀、
  只调用 `/api/tile`。
- 纯函数（分段、色带分位、配速窗口）从内联 JS 里用正则抽出，在 node 下用小样本
  断言边界：末段不足 1km、恰好整除、无时间戳、单点轨迹。
- `tests/test_e2e.py` 增加：`GET /report.html` 返回 200 且含关键标记。

## Risks / Trade-offs

- **Windy 首访慢** → 服务端缓存 + 单次瓦片上限 + 进度提示；失败按瓦片粒度降级。
- **长图很高、2× 倍率内存吃紧** → 默认 1×，倍率可调，超阈值自动降级。
- **GPS 停顿与信号漂移扭曲配速** → 分位裁剪 + 停滞点断开 + 平滑窗口，
  但仍可能与运动手表显示的配速有差；分段表以距离/时间直接换算，保证可复算。
- **速度着色对小样本不友好** → 点数过少（< 20）或速度全相同时退回单色轨迹，
  并在图例注明。
- **中文排版跨平台差异** → 使用系统字体栈（PingFang SC / Microsoft YaHei / sans-serif），
  不下载字体。
- **复制解析代码导致两处行为漂移** → 分析页只解析 `trkpt`，且测试只断言本页要素；
  若后续要统一，再抽公共脚本（本次不做）。

## Migration Plan

- 纯新增静态页 + 门户卡片，无数据迁移、无接口变更。
- 发布：随仓库提交，CI 按 tag 部署；回滚只需还原这两个 HTML 文件。
- 兼容性：无本地存储写入，用户旧数据不受影响。
