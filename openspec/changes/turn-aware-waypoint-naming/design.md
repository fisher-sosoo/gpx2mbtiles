# Design

## Context

现有几何模块 `app/kml_naming.py` 已有 `haversine_m`、`track_stats`（累计里程）与
`_TrackIndex`（最近点定位）。转向计算复用这些，不引入新依赖。

实测基线（洛亚大转 24768 点）：90m 弦长 + 50m 采样 + 50° 阈值 + 250m 合并 →
42 个转向点，密度 1/1.18km，符合山区路线直觉。

## Goals / Non-Goals

**Goals:**

- 给任意轨迹位置一个稳定的「转角」数值，供提示词与摘要使用。
- 噪声不能产生假转向。

**Non-Goals:**

- 不做路径匹配（map matching）到路网，只做纯几何。
- 不改未开启 AI 时的命名规则。

## Decisions

### D1 · 转角定义：进入航向 → 离开航向

在位置 `i` 处，取 `span`（默认 50m）距离：

    heading_in  = bearing(点[i-span], 点[i])
    heading_out = bearing(点[i], 点[i+span])
    turn = normalize(heading_out - heading_in)   # (-180, 180]

负=左转，正=右转。这个定义直观对应「走到这里拐了个弯」。

**替代方案**：用三点夹角 —— 否决，夹角无法区分左右，还得额外算叉积方向。

### D2 · 弦长而非相邻点

GPS 抖动下相邻两点航向是噪声。用跨 `span` 米的弦算航向，
相当于低通滤波。实测 90m 弦长时 42 个转向点密度合理；
25m 采样 + 50m 弦长组合在本样本上表现最好。

### D3 · 阈值：≥ 50° 才算转向，≥ 120° 算发卡弯

50° 以下在山路上极为常见（绕树、避石），标出来全是噪音。
120° 以上基本只有发卡弯和折返。

### D4 · 只在 AI 开启时进入提示词

规则命名（位置名）保持 `#07 3.07km · 1:08`，不加转向。
理由：位置名是「客观定位」，转向是「主观描述」，混在一起会变长且不一致。

### D5 · 摘要始终返回转向

即使不开 AI，摘要也带转向字段——页面可展示，用户能核对；
也让后续「行前指南」直接复用，不必重算。

## Risks / Trade-offs

- **[不同轨迹采样率差异大]**（1 秒 vs 30 秒一点）→ `span` 用米而非点数，
  自动适配；点数不足时返回空而不报错。
- **[往返路线会造成「假发卡弯」]** → 折返点本来就是 180°，属真实情况，
  提示词里让模型结合海拔判断是折返还是发卡弯。
- **[计算开销]** → 每个航点只做两次 O(span) 的窗口查找，航点数通常 < 100，
  可忽略。
